# User guide

## What this runs

The runnable artifact is the headless **Timing Point Application (SI-01)**.

Build it with the repository Maven Wrapper, then run:

```bash
java -jar app/target/timing-point-app-<version>.jar config/application.yml
```

The configured process remains running until a normal shutdown request.

## Configuration

The current public example configuration is `config/application.yml`.

It configures:
- TimingNode identity;
- local TimingData storage;
- Remote Shell listener;
- IF-03 HTTP listener;
- IF-03 WebSocket event listener;
- logging/file retention and optional live diagnostics.

The authoritative configuration semantics are defined by IF-11 in the companion meta
repository. This manual describes only how the current Java executable consumes them.

## Public/development interfaces

Current development endpoints from the default local example include:

```text
GET /api/v1/version
GET /api/v1/status
GET /api/v1/capabilities
POST /api/v1/node/{id}/open
POST /api/v1/node/{id}/close
GET /api/v1/node/{id}/logbook
POST /api/v1/dev/node/{id}/auto-reg
WS /api/v1/events
```

Exact semantic contracts belong to IF-03/IF-05 in the meta repository.

## Local/remote shell

The line-oriented command session supports:

```text
help
version
status
quit
exit
```

The Remote Shell is a development/service endpoint, not SSH or Telnet.

## Development Client

For interactive public-interface inspection use the standalone Java 17 / JavaFX
Development Client:

```powershell
.\mvnw.cmd -f test-client\pom.xml javafx:run
```

See [test-client/README.md](../test-client/README.md).

## Verification versus normal use

The Development Client is an engineering client, not SI-02. Formal black-box pass/fail
verification is owned by the VTS and the `system-test` profile or explicitly manual VTS
cases.
