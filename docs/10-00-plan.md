# Implementation plan and authority

## Purpose

This repository does not maintain a second product roadmap.

Current implementation sequence is owned by the companion meta repository's
[Software Implementation Plan](https://github.com/brainboxemb/2026-010-01.meta.event-timing-software/blob/main/docs/11-SIP-software-implementation-plan.md).

Live implementation state is determined from:
1. that SIP and its current step/activity data;
2. open issues and pull requests in this repository;
3. source/tests on the relevant branch;
4. exact CI and retained generated evidence.

## Local planning rule

A Java issue/PR may refine how an allocated implementation activity is executed, but it
shall not silently redefine product requirements, interfaces or architecture owned by the
meta repository.

If current code and the accepted meta design differ, treat that as a design/review issue;
do not update documentation to make the implementation authoritative by accident.

## Current cross-repository boundary

The ongoing documentation-role audit has identified already-merged simulated-input and
runtime-observability work as implementation evidence that still requires the corresponding
meta design review before being treated as accepted architecture. Keep that distinction
visible in local implementation documentation.
