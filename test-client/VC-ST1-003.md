# VC-ST1-003 — SI-02 Engineering Client lifecycle/revoke/recovery

This repository-local checklist mirrors the manual execution of
`VC-ST1-003` from the meta-repository VTS. The VTS remains authoritative; this
file adds only Java-repository execution details for the real packaged SI-02
Engineering Desktop Client.

The case verifies what the headless server tests cannot prove by themselves:

- lifecycle `NODE_INFO` records stay in the technical LogBook and do not appear
  as registration rows;
- an automatic ADD appears as one interpreted AUTO registration;
- the trash action uses the public node-scoped revoke operation;
- the ADD remains immutable and a separate REV is appended;
- the interpreted registration remains visible as `DELETED`;
- restart/reconnect rebuilds the same interpretation from committed history.

## Prepare

Use one intended Java source revision for SI-01 and SI-02.

Use JDK 21 to build the repository and create the SI-02 app-image:

```powershell
.\mvnw.cmd package -DskipTests
.\test-client\package-windows.ps1
```

SI-01 targets and is executed on Java 8 for this case. The SI-02 app-image carries
its own Java 21 runtime, so the manual GUI run does not depend on the shell's active
Java after packaging.

The verification configuration uses dedicated storage:

```text
config\vc-st1-003.yml
data\vc-st1-003-node-A-logbook.jsonl
```

For a fresh run, remove only the dedicated node-A LogBook file:

```powershell
Remove-Item -Force data\vc-st1-003-node-A-logbook.jsonl -ErrorAction SilentlyContinue
```

Do not remove it between the first run and the restart part of this case.

## Start SI-01

From Java 8:

```powershell
java -jar app\target\timing-point-app-<version>.jar config\vc-st1-003.yml
```

Expected local endpoints:

```text
HTTP       http://127.0.0.1:8081
WebSocket  ws://127.0.0.1:8082/api/v1/events
Shell      127.0.0.1:8023
Live logs  127.0.0.1:8030
```

## Start the packaged SI-02 Engineering Client

From the repository root, start the app-image built during preparation:

```powershell
.\test-client\target\jpackage\EventTimingEngineeringClient\EventTimingEngineeringClient.exe
```

Starting it from the repository root keeps the normal
`config\engineering-client.properties` lookup in effect.

In the top target bar:

1. verify/edit the target host;
2. choose **Apply target**;
3. choose **API CHECK** and verify **READY**;
4. connect **Events**.

The Timing view must show **SYNCING** before it becomes **LIVE**. State-changing
controls remain disabled until the status/capabilities/LogBook baseline is
complete.

## Verification flow

1. With empty storage, verify TimingNode `A` is `CLOSED` with no current
   LocationId and the Timing view is **LIVE**.
2. Enter LocationId `24` and choose **Open**.
   - operation result is `OPENED`;
   - node state becomes `OPEN`;
   - technical LogBook sequence **1** is `NODE_INFO / OPEN`;
   - the lifecycle record does not create a row in **Registrations**.
3. Enter registration `RT-A-0001` with a deterministic date/time and choose
   **Send auto-reg**.
   - operation result reports sequence **2**;
   - technical LogBook sequence 2 is `AUTO_REG / ADD`;
   - the interpreted **Registrations** view contains one AUTO row;
   - the row is not deleted;
   - RegistrationId remains visible in the technical LogBook;
   - the trash action is enabled for the interpreted row.
4. Activate the row's trash action.
   - operation result reports sequence **3**;
   - technical LogBook sequence 3 is `AUTO_REG / REV`;
   - sequence 3 repeats the original LocationId, RegistrationId and registration
     time;
   - sequence 2 remains unchanged;
   - both ADD and REV remain visible in technical history;
   - the interpreted registration row remains present and now shows
     **DELETED** instead of disappearing.
5. Choose **Close**.
   - operation result is `CLOSED`;
   - technical LogBook sequence **4** is `NODE_INFO / CLOSE`;
   - node state becomes `CLOSED`.
6. Verify the technical LogBook now contains exactly the source history:
   - seq 1 — `NODE_INFO / OPEN`;
   - seq 2 — `AUTO_REG / ADD`;
   - seq 3 — `AUTO_REG / REV`;
   - seq 4 — `NODE_INFO / CLOSE`.
7. Connect **Device Log** and verify it remains independent from **Client Log**.
   Changing the runtime log level of one must not change the other.

## Restart / recovery

1. Stop SI-01 through the supported control path, for example by entering
   `quit` in the Engineering Client **Terminal**.
2. Keep `data\vc-st1-003-node-A-logbook.jsonl`.
3. Restart SI-01 with the same verification configuration.
4. Choose **API CHECK** and reconnect **Events**.
5. Verify the Timing view enters synchronising/reconnecting state before
   becoming **LIVE**.
6. After baseline recovery verify:
   - status is `CLOSED` with no operational LocationId;
   - technical LogBook sequences **1..4** are restored unchanged;
   - lifecycle records still do not appear as interpreted registrations;
   - the one interpreted registration is still shown as **DELETED**;
   - recovered history is not added again as new live
     `TIMING_DATA_COMMITTED` events;
   - the client reaches **LIVE** only after baseline/history reconciliation.
7. Verify **Client Log** remains available independently and shut SI-01 down
   cleanly.

## Time display check

The Engineering Client displays registration input as local civil time and
converts it to canonical UTC for IF-03. When using `Europe/Amsterdam`, verify
the displayed zone and the matching UTC value in the technical record.

The technical LogBook is deliberately a raw diagnostic view. Verify the
committed IF-05 v1 representation directly rather than relying on presentation
padding:

- registration/lifecycle `time` has exactly two fractional digits, for example
  `2026-10-07T16:21:57.90Z`;
- `recTime` has exactly three fractional digits, for example
  `2026-10-07T16:22:13.056Z`;
- trailing zeroes remain visible.

This check is presentation/integration evidence; the registration identity used
for REV must remain the original committed time.
